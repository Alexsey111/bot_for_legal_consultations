# Legal Consultation Bot

Telegram бот для юридических консультаций по Гражданскому кодексу РФ.

## 📋 Описание

Бот предоставляет автоматизированные юридические консультации с использованием RAG (Retrieval-Augmented Generation) технологии. Основа знаний — Гражданский кодекс РФ, который индексируется в векторной базе данных для семантического поиска.

### ✨ Основные возможности

- 🔍 **Семантический поиск** по статьям ГК РФ
- 🤖 **Генерация ответов** с помощью LLM (OpenAI)
- 📅 **Запись на консультацию** к юристу
- ❓ **FAQ раздел** с популярными вопросами
- 📊 **Мониторинг** через Prometheus
- 🔐 **Шифрование** персональных данных (PII)
- ⚡ **Rate Limiting** защита от спама
- 💾 **Сессии пользователей** с историей диалога

## 📦 Установка

### Требования

- Python 3.11+
- Redis 7+
- Docker & Docker Compose (для контейнеризации)
- OpenAI API ключ

### Установка через Docker (рекомендуется)

1. **Клонируйте репозиторий:**
   ```bash
   git clone <repository-url>
   cd bot_for_legal_consultations
   ```

2. **Создайте `.env` файл:**
   ```bash
   cp .env.example .env
   ```

3. **Заполните секреты в `.env`:**
   ```env
   TELEGRAM_TOKEN=your_bot_token_here
   OPENAI_API_KEY=your_openai_key_here
   ```

4. **Запустите через Docker Compose:**
   ```bash
   docker-compose up -d
   ```

5. **Проверьте логи:**
   ```bash
   docker-compose logs -f
   ```

### Локальная установка

1. **Клонируйте репозиторий:**
   ```bash
   git clone <repository-url>
   cd bot_for_legal_consultations
   ```

2. **Создайте виртуальное окружение:**
   ```bash
   python -m venv .venv
   ```

3. **Активируйте виртуальное окружение:**
   ```bash
   # Windows
   .venv\Scripts\activate
   
   # Linux/Mac
   source .venv/bin/activate
   ```

4. **Установите зависимости:**
   ```bash
   pip install -r requirements.txt
   ```

5. **Создайте `.env` файл:**
   ```bash
   cp .env.example .env
   ```

6. **Заполните секреты в `.env`:**
   ```env
   TELEGRAM_TOKEN=your_bot_token_here
   OPENAI_API_KEY=your_openai_key_here
   REDIS_URL=redis://localhost:6379/0
   DATABASE_URL=sqlite+aiosqlite:///./data/legal_bot.db
   ```

7. **Запустите Redis:**
   ```bash
   docker run -d -p 6379:6379 redis
   ```

8. **Инициализируйте базу знаний (при первом запуске):**
   ```bash
   python ingest_data.py
   ```

9. **Запустите бота:**
   ```bash
   python main.py
   ```

## ⚙️ Конфигурация

### Переменные окружения

| Переменная | Описание | По умолчанию |
|------------|----------|--------------|
| `TELEGRAM_TOKEN` | Токен Telegram бота (от @BotFather) | — |
| `OPENAI_API_KEY` | API ключ OpenAI | — |
| `REDIS_URL` | URL для подключения к Redis | `redis://localhost:6379/0` |
| `DATABASE_URL` | URL базы данных SQLite | `sqlite+aiosqlite:///./data/legal_bot.db` |
| `METRICS_PORT` | Порт для Prometheus метрик | `9090` |
| `RATE_LIMIT_REQUESTS` | Макс. запросов за окно | `10` |
| `RATE_LIMIT_WINDOW` | Окно rate limiting (сек) | `60` |
| `SESSION_TIMEOUT_MINUTES` | Таймаут сессии (мин) | `30` |
| `SESSION_MAX_HISTORY` | Макс. записей в истории | `5` |
| `CLEANUP_THRESHOLD_DAYS` | Порог очистки старых данных (дни) | `365` |
| `PRODUCTION` | Режим продакшена (включает шифрование) | `false` |
| `ENCRYPTION_KEY` | Base64 ключ для шифрования PII | — |
| `CHROMA_PERSIST_DIR` | Путь к локальной базе Chroma | `./chroma_legal_db` |
| `RELEVANCE_HARD_COSINE` | Жёсткий порог близости: ниже — вопрос считается не по теме | `0.33` |
| `RELEVANCE_SOFT_COSINE` | Мягкий порог, ниже которого нужна проверка покрытия слов | `0.45` |
| `RELEVANCE_MIN_COVERAGE` | Доля значимых слов вопроса, найденных в статьях | `0.34` |
| `STRICT_UNCERTAIN_WORDING` | Строгий режим оговорок: отклонять ответ вместо пометки | `false` |

### Проверка ответов

Перед отправкой ответ проходит четыре проверки: ссылка на статью, отсутствие
выдуманных статей, длина и оговорки.

**Ссылка на статью.** Если в ответе нет ссылки, он всё равно отправляется —
внизу появляется строка «в ответе нет ссылки на конкретную статью, если нужна
точная норма — спросите: „что говорит статья 454“». Отбрасывать такой ответ
хуже: пользователь теряет верный разбор из-за отсутствия формальности.

**Выдуманные статьи.** Ссылки распознаются в любом падеже и в перечислениях
(«статьёй 196», «статей 196, 200»). Если статьи нет в ГК РФ — ответ отклоняется.
Если статья в кодексе есть, но не попала в выборку поиска — ответ отправляется
с пометкой в лог: норма настоящая, просто не была найдена.

**Оговорки.** Слова «возможно», «вероятно», «я не уверен», «обратитесь
к юристу» означают, что однозначной нормы под ситуацию найти не удалось.
Такой ответ **не выбрасывается**: сверху добавляется видимая пометка
«⚠️ В ответе есть слова вроде „возможно“ или „вероятно“: однозначной нормы
под вашу ситуацию найти не удалось». Причина: выбросить верный разбор из-за
одного слова — ухудшение продукта, а не улучшение.

Строгий режим включается переменной `STRICT_UNCERTAIN_WORDING=true` — тогда
такой ответ отклоняется и пользователь получает обычный текст отказа.
Оба режима покрыты тестами (`tests/test_index_and_wording.py`).

## 📊 Мониторинг

### Prometheus

Бот экспортирует метрики на порт `9090` (по умолчанию).

**Доступные метрики:**
- `bot_messages_total` — общее количество сообщений
- `bot_consultations_total` — количество консультаций
- `bot_errors_total` — количество ошибок
- `bot_response_time_seconds` — время ответа

**Просмотр метрик:**
```bash
curl http://localhost:9090/metrics
```

### Логи

Логи выводятся в stdout и могут быть настроены через `structlog`.

## 🔒 Безопасность

### ВАЖНО - Безопасность

**НЕ коммитьте в репозиторий:**
- `.env` файлы
- `data/.encryption_key`
- `*.db` файлы баз данных
- Логи с персональными данными
- API ключи и секреты

### Шифрование PII

В продакшен-режиме (`PRODUCTION=true`) персональные данные шифруются перед сохранением в базу данных.

**Генерация ключа шифрования:**
```python
from cryptography.fernet import Fernet

key = Fernet.generate_key()
print(key.decode())  # Сохраните в ENCRYPTION_KEY
```

### Rate Limiting

Защита от спама ограничивает количество запросов от пользователя (по умолчанию: 10 запросов за 60 секунд).

## 🐛 Troubleshooting

### Бот не отвечает на сообщения

1. Проверьте, что запущены Redis и бот
2. Проверьте логи: `docker-compose logs -f`
3. Убедитесь, что `TELEGRAM_TOKEN` верный

### Ошибка при загрузке базы знаний

1. Проверьте наличие файла `knowledge_base/gk_rf.txt`
2. Убедитесь, что `OPENAI_API_KEY` активен
3. Попробуйте перезапустить загрузку: `python ingest_data.py`

### Redis недоступен

```bash
# Проверьте статус Redis
docker ps | grep redis

# Перезапустите Redis
docker-compose restart redis
```
